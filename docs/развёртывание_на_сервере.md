# Развёртывание платформы на сервере (WB + Ozon, 24/7)

Пошагово: от чистого сервера до работающей автоматизации.
Предполагается Ubuntu/Debian. Команды выполняются по SSH под пользователем с sudo.

---

## 0. Что понадобится
- Доступ к серверу по SSH.
- Ключи: `ANTHROPIC_API_KEY`, WB-токен(ы), Ozon `Client-Id`+`Api-Key`.
- Доступ к репозиторию (этот проект).

---

## 1. Базовые пакеты
```bash
sudo apt update && sudo apt install -y python3 python3-venv python3-pip git
```

## 2. Забрать проект
```bash
sudo mkdir -p /opt/k-beauty && sudo chown $USER /opt/k-beauty
cd /opt/k-beauty
git clone <URL_репозитория> .
# или скопировать проект, если репо приватный
```

## 3. Виртуальное окружение и зависимости
```bash
cd /opt/k-beauty
python3 -m venv .venv
source .venv/bin/activate
pip install requests python-dotenv pyyaml openpyxl
```

## 4. Настроить ключи (.env)
```bash
cp .env.example .env
nano .env          # вписать реальные значения
chmod 600 .env     # доступ только владельцу
```
Заполнить:
```
ANTHROPIC_API_KEY=...
WB_TOKEN_KOROTICH=...
WB_TOKEN_KRONA=...
OZON_CLIENT_ID_KOROTICH=...
OZON_API_KEY_KOROTICH=...
TG_BOT_TOKEN=...        # опционально, для уведомлений
TG_CHAT_KOROTICH=...
```

## 5. Настроить клиентов (реестр)
```bash
cp mp_platform/clients/clients.example.yaml mp_platform/clients/clients.yaml
nano mp_platform/clients/clients.yaml
```
На старте оставить ВСЕ задачи в режиме **suggest** (только предлагать, ничего не менять):
```yaml
automation:
  ads:     suggest
  seo:     suggest
  pricing: suggest
  stock:   suggest
```

## 6. Проверить связь с кабинетами
```bash
source .venv/bin/activate
# Ozon
python -c "from mp_platform.config import load_clients; from mp_platform.connectors.ozon import Ozon; print(Ozon(load_clients()[0]).stocks()[:2])"
# WB реклама
python -c "from mp_platform.config import load_clients; from mp_platform.connectors.wb import WB; print(WB(load_clients()[0]).campaigns()[:3])"
```
Если вернулись данные — ключи рабочие.

## 7. Первый прогон — РЕЖИМ СБОРА (ничего не меняет)
```bash
mkdir -p logs
python -m mp_platform.runner all stock      # остатки
python -m mp_platform.runner all ads        # анализ рекламы (только отчёт)
```
Проверить: в `data/platform/` появились данные, в Telegram пришли сигналы,
в журнале (`data/platform/platform.db`, таблица actions) статусы `awaiting_approval`.

## 8. Повесить на расписание (cron)
```bash
crontab -e
```
Вставить строки из `mp_platform/crontab.example` (поправить пути `/opt/k-beauty` и `.venv`).

## 9. Включение автодействий — ПОСТЕПЕННО
Когда убедишься, что сигналы корректны:
1. В `clients.yaml` переключить **ads: auto** (сначала только реклама — самое безопасное: пауза кампаний без заказов).
2. Понаблюдать несколько дней по журналу.
3. Затем **pricing: auto** (цены — строго в рамках guardrails: не ниже ROI, не больше лимита изменения).
4. `stock` — оставить сигналами (поставка — физический процесс).
5. `seo` — оставить suggest (публикация карточек после проверки).

---

## Безопасность (обязательно)
- `.env` — `chmod 600`, никогда не в git.
- Начинать ВСЕГДА с режима suggest, автодействия включать по одному.
- Все действия пишутся в журнал — проверяй его регулярно.
- Для нового клиента: отдельный блок в `clients.yaml` + его ключи в `.env`.

## Обновление кода
```bash
cd /opt/k-beauty && git pull && source .venv/bin/activate && pip install -r requirements.txt 2>/dev/null
```

## Если что-то упало
- Логи: `logs/*.log` и вывод cron.
- Проверить ключи (`.env`), лимиты API (429 = слишком часто), срок WB-токена (~180 дней).
